## 建议

文档和代码用同一个 Git 仓库，就是现在这个 `dreaming-room`。

产品定义、批示和实现要能对上。分开两个仓库之后，一次改动要提交两次，版本记录也拆成两处。UE5 工程以后如果太大，再单独立项决定要不要把大文件挪走。这次不拆仓库。

代码不放进 `Documents/`。`Documents/研发部/` 继续只放规格。

代码放在仓库根的 `Code/`：

| 路径 | 放什么 |
| :--- | :--- |
| `Code/Workbench/` | 定制工作台 |
| `Code/Viewer/` | 观看页 |
| `Code/UE5/` | 本机 UE5 工程 |

这三个名字对应产品需求文档里的两个软件和本机 UE5。现在不建空目录。哪一块要写代码，在那次已同意的任务里建立对应文件夹。

Git 仍是现在这一个，分支仍是 `master`。

- 产品正文版本仍按批示升。只改代码、不改产品正文时，不升 v1.7，也不往版本记录加行。
- 写代码的提交说明里写任务编号，例如 P1-3，并写它对应的产品需求文档章节。
- 开工条件不变：任务书已同意，依赖的待定项已确认，内容能指回产品需求文档和研发规格。这次批示不代替那次同意。
- UE5 的中间文件（`Intermediate`、`Saved`、`DerivedDataCache`、`Binaries`）不提交。工程真的建起来时再写 `.gitignore`。大文件要不要另存，到那时再定。

## 子 agent 遵守的规范

位置写在目录里不够。写代码的子 agent 要有一份单独的规范，不靠对话记忆。

规范放在 `Documents/研发部/07-代码规范.md`。研发子 agent 写代码前先读它。`.cursor/rules/doc-authority.mdc` 加一句：写代码先读这份规范。这句话保持很短，不把规范全文放进每次对话。

规范只写这几条：

1. 代码只放在 `Code/Workbench/`、`Code/Viewer/`、`Code/UE5/`。不放进 `Documents/`，也不另建目录。
2. 没有已同意的任务，不建目录，不写代码。任务依赖的待定项未确认，该任务不写。
3. 改动必须能指回任务编号和产品需求文档的章节。不增加任务书以外的功能。定制工作台的开发语言在 D11 确认前不选定。
4. 提交说明写任务编号和对应章节。只改代码、不改产品正文时，不升版本，不改版本记录。
5. 不提交密钥、账号和 UE5 的 `Intermediate`、`Saved`、`DerivedDataCache`、`Binaries`。
6. 做完的结果写在工单上。不在 `Code/` 里另写一套需求。
