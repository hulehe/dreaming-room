# 待批示：版本号怎么区分产品描述和代码

日期：2026-11-14 22:05:54  
增补：2026-11-14 22:10:06  
来源：你指出界面风格大改而功能不变时不升版本不合适，并问研发部的界面、细节功能和模块定义是否也要版本管理。你要求把版本号的定义写全，写明它怎样反映产品描述的变化和代码的更改。  
对应批示：027。027 规定只改代码、不改产品正文时不升版本。这次写明什么是产品描述、什么是代码更改。不改产品功能条款。不同意就维持现在的写法：目录只说「改了正文，次版本加 1」，正文范围仍不单列界面、细节和模块。

## 版本号表示什么

产品版本写成 `v主.次`。它只表示写成文字的产品现在是哪一版。全仓库同时只有一个当前产品版本，写在 `Documents/目录.md`。

代码没有单独的产品版本，也不加第三段数字。代码的版本就是 git 提交号。提交说明写明它在实现哪一个产品版本。这样两边都能看见：产品描述变了，版本号变；代码按已写明的描述去实现，版本号不变，提交号变。

`v主.次.修订` 不采用。每次改代码都出现一个新的产品版本号，版本记录里就分不清产品变了还是代码变了。

## 主版本

主版本在你书面宣布「这一版对外交付的范围已经冻住」时加 1，次版本归零。

- v0：目录还在收拢。
- v1：目录已经冻结（批示 017）。产品定义仍可改。还没有一版可交付的软件。现在是 v1.7。
- 下一次主版本：你书面确认，这一版要做什么、界面是什么样、模块怎么分，都已经冻住，此后只改代码去实现这一版。

批准任务书、开始写代码、做出 Demo，都不因此升主版本。第一阶段仍留在 v1。冻住之后若又要改产品描述，另一次批示，次版本加 1，主版本保持不动，直到你再书面宣布进入下一版可交付产品。

目录里「一个阶段的范围冻结时，主版本加 1」改为上面这一条。按原句，第一阶段任务书一同意就会变成 v2.0，当时产品定义可能还在改。

## 次版本

次版本在产品描述的含义变了时加 1。一次批示里改了多处，次版本只加 1。含义按下面四类算，功能清单没变也算。

1. 做什么。产品需求文档里的功能、范围、用户能得到的交付。
2. 看起来怎样。界面的布局、视觉风格、控件外观、屏上文字、用户看得到的动效。功能相同，风格改了，次版本加 1。
3. 细节行为。状态怎么转换、等待和超时、失败时怎样、一次交互的结果。
4. 模块与接口。模块的边界、模块之间传递什么。使用的人看不见，写代码的人要按它做，所以写明的模块定义变了，次版本加 1。

这四类现在的文字在这些文件里：`Documents/上层决策/产品/产品需求文档.md`，以及 `Documents/研发部/` 的 `01-范围与阶段.md`、`02-状态机.md`、`03-模块与接口.md`、`04-分系统规格.md`。界面规格还没有单独文件。第一次要定界面时，在研发部新增一份界面规格；这次新增本身是产品描述，次版本加 1。这次不新建该文件。

## 不升版本

下面这些改动不升主版本，也不升次版本。

- 笔误、文件改名、路径调整、目录分类。执行时做成的东西与改前相同。
- 批示、待批示、存档、工单、版本记录。
- 维护说明、部门说明、代码规范、宣传规则、市场任务书、市场待定项。这些是做法和宣传约束。它们若要求产品变成另一个东西，先改产品描述，由那一次改动升次版本。
- 待定项只保持待确认。确认结果写进了上面四类产品描述时，由那一次写入升次版本。
- README 跟着当前产品描述改介绍和链接。它不是第二份规格，不单独升版本。
- 只改代码，做出的行为和界面与当前文字一致。包括把功能做完、把界面做成规格里已经写好的样子、修理到与规格一致、在不改变写明模块的前提下调整内部结构。
- `Media/` 里的实拍、小视频、宣传册。工单写明它对应的 `v主.次`。成片本身不升版本。

## 代码怎样反映

代码提交说明的第一行写 `实现 v主.次`，并写任务编号和产品需求文档的章节。读提交的人能看出：产品版本是哪一版，这次变的是代码。

工单的结果里写依据的产品版本和提交号。版本记录不追加这种提交。

代码若做出当前文字里没有的功能、界面、细节行为或模块边界，不能当作「只是实现」提交。先写入待批示。你批示之后，改产品描述，次版本加 1，再按新版本写代码。

## 文件头和版本记录

当前产品版本只看目录。单份文件头上的版本，是这份文件上次被改写时的产品版本。这一轮改过的产品描述文件，文件头写成新版本。这一轮没改的文件保持原文件头。所以状态机可以仍标 v1.5，目录写当前是 v1.7：表示状态机从 v1.5 之后没有改含义。

两次批示都还没提交时，文件头只留后一个版本号。版本记录只记提交成功的那一个。v1.4 并进 v1.5、v1.6 并进 v1.7 的做法继续用。

版本记录只记产品版本。变更栏写明改的是功能、界面、细节行为，还是模块与接口。你在对话里要求提交并且提交成功之后才追加。提交前不写入。
