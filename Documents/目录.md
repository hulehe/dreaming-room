## 权威顺序

1. `Documents/上层决策/产品/` 里的 PRD
2. `Documents/上层决策/批示/` 里已写入的批示
3. 各部门规格中状态为「已确认」的条款
4. 状态为「建议」的条款，只供审阅

你只做最上层批示。聊天记录、`Documents/上层决策/待批示/`、`Documents/上层决策/存档/` 不是需求。每一级的计划、执行和结果以该级文档为准，不依据对话。

上一级把下一级要完成的事写成工单。工单必须引用上一级依据：最上层是批示编号，再往下是上一张工单。没有工单，下一级不改仓库。命令不得超出上一级文档。子部门由其上一级部门负责，不把执行细节跳级送到最上层。

现在最上层的下一级是研发部和市场部。以后某部门内设子部门，工单写在该部门自己的 `下发工单/` 里，由该部门管理。结果写在同一张工单上。只有上一级文档没有覆盖、或要改 PRD 的事项，才逐级写入待批示并停工，直到需要你批示。

## 版本

产品版本写成 `v主.次`。它表示写成文字的产品现在是哪一版。当前产品版本以本节为准。单份文件头上的版本，是该文件上次被改写时的产品版本。代码没有单独的产品版本，也不加第三段数字。代码的版本是 git 提交号。提交说明第一行写 `实现 v主.次`，并写任务编号和产品需求文档的章节。

主版本在你书面宣布「这一版对外交付的范围已经冻住」时加 1，次版本归零。v0 是目录收拢期。v1 是目录已冻结（批示 017），产品定义仍可改，还没有可交付的软件。批准任务书、开始写代码、做出 Demo，都不因此升主版本。冻住之后若再改产品描述，次版本加 1，主版本保持不动，直到你再书面宣布进入下一版可交付产品。

次版本在产品描述的含义变了时加 1。一次批示里改了多处，次版本只加 1。四类都算：

1. 做什么。产品需求文档里的功能、范围、用户能得到的交付。
2. 看起来怎样。界面的布局、视觉风格、控件外观、屏上文字、用户看得到的动效。
3. 细节行为。状态怎么转换、等待和超时、失败时怎样、一次交互的结果。
4. 模块与接口。模块的边界、模块之间传递什么。

这四类的文字在 `Documents/上层决策/产品/产品需求文档.md`，以及 `Documents/研发部/` 的 `01-范围与阶段.md`、`02-状态机.md`、`03-模块与接口.md`、`04-分系统规格.md`。界面规格在第一次要定界面时写入研发部，这次新增算产品描述。

不升版本：笔误、文件改名、路径调整、目录分类；批示、待批示、存档、工单、版本记录；维护说明、部门说明、代码规范、宣传规则、市场任务书、市场待定项；待定项只保持待确认；README；只改代码且做出的行为和界面与当前文字一致；`Media/` 里的实拍、小视频、宣传册。宣传规则或市场任务书若要求产品变成另一个东西，先改产品描述，由那一次改动升次版本。确认待定项的结果写进产品描述时，由那一次写入升次版本。成片和代码的工单写明对应的 `v主.次`。

代码若做出当前文字里没有的功能、界面、细节行为或模块边界，先写入待批示。批示改产品描述、次版本加 1 之后，再按新版本写代码。

这一轮改过的产品描述文件，文件头写成新版本。没改的文件保持原文件头。两次批示都还没提交时，文件头只留后一个版本号。改本节对主版本、次版本的定义，次版本加 1。

`Documents/版本记录.md` 只记录已经 commit 成功的产品版本，并写上提交号。变更栏写明改的是功能、界面、细节行为，还是模块与接口。你在对话里要求 commit 且这次提交成功之后，才追加该版本。提交前不写入。已提交的是 v0.1、v0.2、v1.0、v1.1、v1.2、v1.3、v1.5 和 v1.7。v0.3 从未提交成功，不记。v1.4 与 v1.5 写在同一次提交里，只记 v1.5。v1.6 与 v1.7 写在同一次提交里，只记 v1.7。v1.8 尚未提交，不记。

版本更新的当次回复写明版本号、改了哪些文件、为什么改。你明确说提交之前，不做 Git 提交。

你批示之后，待批示文件移到 `Documents/上层决策/存档/`。该批示若要下一级交付，直接上一级写成工单并交给下一级执行，不就已有文档里的细节再请你决定。结果写回该工单，并在回复里汇报。

研发部不写宣传文案。市场部不改产品规格，不把调查推断写进 PRD。市场材料里的能力必须能指到 PRD，或指到研发部已经完成的交付物。

在你书面同意某一份任务书之前，不派子 agent 写代码、不建 UE5 工程、不采购或接通外部模型服务，也不制作小视频或 PPT。Demo 有可观看的实现之前，市场部不制作宣传材料（批示 002）。批示 018：研发第一阶段先不开工；Demo 前只做产品定义调查，证据用公开信息。

## 日期

批示、待批示、存档和工单的文件名、文内「日期」都写到秒。文内用 `YYYY-MM-DD HH:MM:SS`。文件名把时刻接在日期后面：`YYYY-MM-DD-HHMMSS`。时区用本地时间，现在是 UTC+9。来源报道里的日期不改。已经写过的文件，秒用它第一次进入 git 的提交时间，不另编。
