# 体验状态机

版本：v0.1 · 2026-11-13 · 批示 005

依据 PRD 第 1、2、3.2、4 节。本文件把这几节收成一套状态，避免「屋里一直有人在生活」和「无人时释放 GPU」各做各的。

## 必须同时成立的两句话

- 无人时，家属看到的是数字人在屋内的日常，或屏幕处于息屏待机。
- 无人时，云端 GPU 实例释放或休眠，月度算力按「有人在场才占用」计算。

因此，无人期画面是终端本地播放的预渲染日常循环，或息屏。UE5 实时会话只在人靠近之后的云端会话里运行。Behavior Tree 的无人分支用来制作这条预渲染循环，也用来准备「人已离开、会话尚未释放」的短窗口；它不要求 GPU 全天在线。

息屏与预渲染微动都是 PRD 写明的休眠表现。默认选用哪一个，见决策 D1。在 D1 确认前，实现不假定默认值。

## 状态

| 状态 | 进入条件 | 屏幕上的事 | 云端 GPU |
| :--- | :--- | :--- | :--- |
| 本地休眠 | 无会话，或会话已释放 | 预渲染日常循环，或息屏 | 释放或休眠 |
| 过渡掩盖 | 传感器上报有人走近 | 立刻播放不超过 5 秒的预渲染过渡：放下手头动作、起身、走向屏幕 | 在这 5 秒内冷启动 |
| 在场会话 | 过渡片结束，实时画面已接上 | 数字人已到摄像机前，微笑，处于倾听或对话姿态 | 占用 |
| 健康告别 | 本次会话对话时长达到已确认的上限 | 自然道别，走回屋内休息 | 仍占用到告别动作结束 |
| 离场释放 | 检测到无人持续超过 30 秒 | 回到本地休眠 | 断开并释放 |

PRD 写的是「数分钟」后道别，没有写死具体分钟数。具体上限是决策 D2。1.0 必须实现告别；第一阶段的 30 秒视频不把「演完数分钟」列为完成标准。

## 时间常量

| 常量 | 值 | 出处 |
| :--- | :--- | :--- |
| 过渡片时长 | 5 秒 | PRD 第 4 节 |
| 无人释放阈值 | 超过 30 秒 | PRD 第 4 节 |
| 对话时长上限 | 未定 | 决策 D2 |
| 走近判定距离 | 未定 | 决策 D4 |

实现使用上表已写明的数值。不另设第二套超时。

## 无缝接管

过渡片的最后一帧与 UE5 会话的第一帧对齐：机位、人物在摄像机前的位置、微笑或倾听姿态一致。实时画面接上时，终端不再叠一层加载画面。5 秒内 GPU 未能交出可显示的实时帧，终端继续停在过渡片最后一帧，会话标记为启动失败并向负责人汇报；规格不增加 PRD 没有的补救剧情。

## 离开与告别的先后

- 对话先到达时长上限：进入健康告别，道别并回屋。告别动作结束后开始计算无人时间，超过 30 秒进入离场释放。
- 人先离开：不播健康告别词，无人持续超过 30 秒后释放。人在 30 秒内回到感应范围，会话保持，数字人保持在场姿态。
- 告别过程中人已不在：告别动作照常做完，随后按 30 秒规则释放。

「道别结束后是否立刻释放」若要改成别的顺序，先改决策 D3。上表是使第 2 节和第 4 节能同时实现的顺序。

## 唤醒动作

收到走近信号后，Behavior Tree 走唤醒分支：寻路到摄像机前，切到倾听与对话姿态，并露出微笑。过渡片表现的是同一次起身走近，用来盖住冷启动，不另写一套剧情。

## 第一阶段如何落到这套状态

第一阶段用本机 UE5 把「日常 → 走近微笑 → 一轮对话」拍进 30 秒视频。云端实例、安卓装机、30 秒释放的联调放到第三阶段。视频里的动作顺序与本文件一致，这样 1.0 接 Pixel Streaming 时沿用同一状态，不改体验定义。
